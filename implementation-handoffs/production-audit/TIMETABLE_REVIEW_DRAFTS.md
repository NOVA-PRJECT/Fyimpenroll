# Catalogue hours and conflict-free review drafts

This release supersedes the fixed MDC contact-hour checks and the historical capacity conclusions in SEMESTER_1_SOLVER_DIAGNOSIS.md. Theory and practical hours come from the catalogue courses referenced by the selected academic-year/semester registrations. Missing, fractional or negative hours are rejected as invalid data; category names no longer prescribe hour totals. The existing 2+1 MDC session structure applies only when the actual catalogue has 3 theory and 0 practical hours.

Generation first attempts a complete timetable with up to 240 seconds of solver search. On infeasibility or an unresolved timeout, it attempts a conflict-free review draft with up to 60 seconds of search. The review model maximizes placed contact periods before soft preferences. It never relaxes student/teacher collisions, teacher reservations, category synchronization, allowed windows, lunch separation or two-period practical blocks. Every missing session records its course, theory/practical type, duration and reason. A practical hour incompatible with the two-period block rule is listed explicitly rather than dropped. Incompatible campus paper options remain synchronized; the solver leaves any remaining hours unscheduled instead of splitting a paper.

The independent validator has an explicit review-only mode that permits missing hours but still rejects excess hours, conflicts, invalid slots/blocks/windows and unsynchronized campus options (including an omitted option). Draft accounting separately reconciles placed and remaining hours with every course's catalogue totals. A review timeout without a verified placement produces an empty preview listing every required session; it never claims a complete timetable.

Review results are durable director-only previews in the existing timetable job's system_logs.metadata. A conditional write checks campus, worker token, running status and lease freshness. It preserves the lease metadata and removes any publishable draft fingerprint. It does not replace timetable_entries, alter a published schedule or save student membership identifiers. Thus no database schema migration is required. The existing database publisher rejects the latest completed job without a validated fingerprint, including when an older complete draft exists. The backend also rejects preview publication regardless of a force flag; the frontend disables publication.

The director receives a clearly marked incomplete grid and an unscheduled-session list after generation and after refreshing. Excel exports label every grid as a review draft and include an unscheduled-session sheet; PDF printouts include the warning and remaining sessions. These exports support manual review. The existing portal does not provide a general drag-and-drop editor for placing remaining sessions: directors can adjust the source catalogue/rules and generate again. Complete results use the existing independently validated, fenced atomic replacement and publication workflow.

The refreshed read-only 2026-27 Semester 1 cohort contains 126 registrations, 18 courses and 30 available periods. All eight MDC options now have 2 theory and 0 practical hours. Statistics DSC has 4 theory and 0 practical hours. No production records were changed by this agent. An anonymized local review-model run placed all 50 course-period entries, including shared simultaneous campus options, with no unscheduled sessions and zero independent validation violations in 2.276 seconds of search. This is a complete feasible schedule; the earlier 32-period conclusion described previous catalogue hours. Local timings are not a guarantee for Render.

Focused tests cover catalogue-driven MDC hours, over-capacity previews, uneven campus options, retained teacher reservations, odd practical remainder reporting, missing-option synchronization, exact remaining-hour accounting, stale-worker rejection and publication blocking through both the API and the actual PostgreSQL publisher.

The ordinary complete-generation model also returned FEASIBLE on the same anonymized cohort: 50 course-period entries in exactly 30 distinct weekly slots, zero independent validator violations, and 30.153 seconds of search including soft-preference optimization. Backend compilation and targeted fallback/authorization tests passed. Frontend type checking, 24 tests, lint and production build passed. The full backend suite initially passed 280 tests with one skipped PostgreSQL concurrency test and one failing authorization mock; that mock was updated for the additional read-only preview check and passed its targeted rerun. Production CI runs the full exact-commit suite and PostgreSQL concurrency test.
